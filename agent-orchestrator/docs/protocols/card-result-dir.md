## 6. The nested form (source-code description)

`dispatch(mission_id, mode:"nested")` numbered exit (the numbered-receipt form):

- **No process spawn, zero result files, zero assembly text**: the in-lock dispatch-face validation (pack parsing + the CONTRACT three-line parsing + token auth) returns the numbered receipt `{ok, mode:"nested", mission_id, worker, channel, token, pack_path, lock_hold_ms}` - the coordinator fills the first message from the receipt fields per the DP-3 fixed-pointer template (SKILL §3), and the worker fetches the pack itself (`pack_path` = an absolute path in the sandbox scenario, feeding the template's "Read the task pack first" slot). The result-dir three-piece set (index/error/result) and model-seed are **entirely absent** for nested: no runner, no seeding, no <=8s combined capture (the wrapper skips on the `__nested` marker).
- **busy gate forks by mode**: the nested in-flight criterion = **board semantics** (status=dispatched and the worker result not yet landed on the board - the dispatch credentials have been handed to the coordinator; running is already intercepted by the status gate), **consuming no result-dir index**; the headless gate (§3/§4, parked archive) judges headless by mission.dispatch.mode and naturally consumes no nested mission. The fork judges by the mission-side mode, not by the request mode. Recovery path = board upsert `status:"drafted"` (the dispatched->drafted legal leg) then re-dispatch, or wait for the worker report.
- **Embedded validation (dispatch discipline is guaranteed by the tool face, §8.7 - bg-gate toward host Agent calls is a prompt face, not a defense line [PT-5]; the bg-gate presence face = runtime real-message audit)**: (1) the CONTRACT three lines - the dispatch face `dispatchParseContract` parsing is mandatory, a missing three lines throws here first; (2) token auth (same semantics as p2pTokenGate) - the pack CONTRACT token must be identical to mission.dispatch.token, and with no board token plus `--strict-tokens` the dispatch is rejected (same direction as the report gate); (3) the scope_paths pre-check - the yolo gate's two forms share one gate (a non-empty write set for worker-class roles).
- **Bookkeeping**: `upsertMission` internal lands `dispatch={mode:"nested", agent_id:null, task_id:null, session_id:null, spawned_by_session}` (the W3 attribution-anchor consumption face; agent_id left empty -> sentinel classify requires agent_id -> **nested is not watched by default**, the coordinator receives directly while present). The audit prompt file drop is **retired**.
- **Completion channels**: the host Agent return + the worker report, dual channels, no wake-queue dependency (producer (1) is limited to `mode==="headless"` [parked archive]; producer (2) is the runner [parked] - nested adds zero new file families).
- **Consumer impact list (M5-1 measured)**: all server-side readers of result-dir sit inside the headless dispatch path (parked); the nested branch returns before these points and naturally consumes none; bg-sentinel and probe make **zero reads** of dispatch-results - a missing result-dir has zero impact on the sentinel/probe.
- **Assertion anchors**: the crv6-resilience NST group (A-v0120-NST; the post-rewrite form = the numbered field set + the negative four-absences / busy-gate three-state fork / the two embedded-validation legs / the schema+wire static locks - NST-01b/01c retired with the disappearance of the prompt-shape/audit-drop subjects).
