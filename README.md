## 这是什么

Agent Orchestrator（中文名「子代理主控台」）是一个 ZCode 插件。它把主会话里的 agent 变成真正的任务指挥官：主控负责拆解任务、派发、答疑、验收；子代理只负责执行并回报结果。

所有任务登记在一张任务板上，进度、产物、阻塞提问一目了然；后台任务收工由钩子自动清点，完成通知丢失还有哨兵自动补枪叫醒主控——适合让主控带着多个子代理跑长链条、多角色的复杂工作。

## 核心能力

- **任务板与依赖编排** — 任务状态机 + 依赖图（DAG）：下游任务在上游签收后自动解锁；支持池工租约制自领取。
- **自包含任务包派发** — 一键物化任务包：任务、规则、文件写集白名单（越界即验收失败）、预算档位、上游产物逐字内联，子代理拿包即可开工。
- **后台并行与收工清点** — 嵌套在场直收与独立后台会话两种派发形态，多个子代理并行跑；会话收尾由 Stop 钩子自动清点在飞任务。
- **问答续跑与恢复** — 子代理卡住可向主控提问，作答后原地续跑；中断任务可跨会话恢复现场。
- **分叉对比** — 同一任务一次派 2–8 个方案变体并行试跑，横向比稿后择优采用。
- **按角色选模型** — 预置执行、侦察、评审等角色，支持运行时创建自定义角色，并为不同角色绑定不同模型。
- **唤醒保障** — 哨兵家族多实例错峰补枪，防"任务其实完成了、主控却没被叫醒"；可选 watcher 守护进程支持远程唤醒。
- **沙箱派发与成本纪律** — 写代码任务隔离进 git worktree，评审通过后安全合并、失败零损伤丢弃；结构化只读探针控制读回开销，经验教训沉淀归敛复用。

## 安装

要求：**Node.js ≥ 20**。

- **插件市场安装**：在 ZCode 插件面板添加本仓库（`hiairuri/Agent-orchestrator`）作为市场源，然后安装「Agent Orchestrator / 子代理主控台」。
- **本地路径安装**：克隆本仓库后，将市场源指向仓库内的 `plugins/` 目录（含 `marketplace.json`）再安装。

安装后编排 MCP 服务器（服务名 `orch`，共 12 个工具）自动注册；任务板、邮箱等运行数据默认落在项目内的插件存储根目录，可在插件设置中改到项目外位置。后台闸门、哨兵、上下文镜像、沙箱默认策略等行为均提供设置项，不配置即用默认值。

## 快速开始

安装插件后，在 ZCode 里对主控说一句"用 agent-orchestrator 帮我并行派三个子代理做 X"，主控会按标准流程编排。一次最小派发的完整闭环：

1. **登记任务**：主控在任务板上建任务条目——标题、允许改动的文件清单（写集）、完成标准。
2. **打包派发**：生成自包含任务包派给子代理——主控在场可嵌套直收结果，也可丢到后台并行跑。
3. **执行回报**：子代理按包内规则干活，经上报工具回报进展：里程碑 / 受阻提问 / 完成。
4. **作答续跑**：子代理提问 → 主控作答 → 子代理原地继续；完成通知丢失 → 哨兵自动补枪提醒主控。
5. **签收解锁**：主控签收结果，依赖它的下游任务自动解锁；写代码任务走沙箱评审后再合并回主分支。

## 架构一览

一句话：**MCP server 单文件零依赖**（Node 标准库实现）+ **7 个 hook 脚本**（覆盖会话恢复简报、后台派发闸门、收工清点、现场记录四类事件）+ **watcher 守护进程（可选，远程唤醒）**。任务板与邮箱以 JSON 文件落盘，不依赖外部服务。
